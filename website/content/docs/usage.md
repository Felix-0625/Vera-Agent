# 日常使用

## 绑定项目并开始对话

选择一个可信的本地目录作为工作项目，再在项目下创建对话。项目路径是任务、会话、工作流实例及运行记录的归属依据。可以在设置中启用读取项目的 `AGENTS.md` 规则；规则会影响 Agent 的上下文，但它不是代码执行权限。

对话会展示可观察的模型文本、工具请求、审批与工具结果。需要修改文件或执行终端命令时，先确认动作、目标路径和参数。**项目绑定不会创建操作系统沙箱。**

## 使用任务看板

在当前项目的看板中创建工作项，设置标题、描述、状态、优先级和标签。工作项可链接同项目的一条对话，便于从任务回到讨论。链接不会自动完成任务；你应检查结果后明确更新状态。归档会从常规列表隐藏工作项。看板记录存于应用级 SQLite 数据库，带 `project_id` 与版本号；过期版本的编辑会被拒绝。

## 子智能体与协作窗口

Vera Agent 可以把适合分工的调研或复核任务交给子智能体。各角色拥有自己的会话，进度与返回结果通过原对话可见。页面应展示角色、任务和结果，不应把模型不可见的内部推理渲染为执行记录。侧边对话用于临时上下文讨论，是否持久化应以具体会话类型为准。

## 自定义组织与工作流

1. 在可视化编辑器中设计模板。**组织架构**（architecture）只能是一棵汇报树：唯一顶层角色、每个角色唯一直接上级、不允许环，且节点必须全是角色（agent）节点；这条规则在创建实例、更新实例、保存模板三处统一校验，不是editor单方面的约定。**工作流**（workflow）定义步骤和连线，可设置条件分支与受限循环，结构更自由。
2. 将模板复制为项目实例，填写该项目的目标与背景，按实际需要修改角色、节点和连线。模板不携带模型凭据。
3. 从项目对话中调用实例，确认运行（需要显式传入确认值）。系统为这次运行创建一批独立于实例本身的隔离会话，运行之间不共享对话历史。
4. 查看节点的输入来源、状态、输出与错误；活动分支的结果传给下游，最终由 Supervisor 复核结果并返回原对话。

**可用的节点类型只有三种：** 不管是组织架构还是工作流，编辑器目前只能添加 **Agent（角色）、Condition（条件）、Loop（循环）** 三种节点，运行时也只为这三种实现了执行逻辑。条件节点必须同时连出 `true`/`false` 两条分支，循环节点必须同时连出"继续"/"退出"两条分支，否则运行时会报错；循环还有 1–20 次的迭代次数上限。接口协议里能看到更多节点类型名称（如 `start`、`code`、`http`），但那些目前只是预留的数据结构，编辑器画不出来、运行时也跑不动。

运行目前由界面按节点**串行调度**，不会并行执行任何分支。刷新或关闭窗口会中断正在调度的运行；已保存的节点状态仍在项目 `.agents/runs/`，但当前没有一键恢复端点——需要重新发起一次运行。详细字段见[数据模型](../../../docs/DATA_MODEL.md#workflow-node-and-edge)。

## 工具、MCP 与 Skill

内置工具覆盖文件、终端、Git、会话和委派等能力。MCP 服务器、Skill 与权限策略在应用设置中配置；其可用性取决于服务或包本身。外部扩展可能读取数据或执行命令，启用前应检查代码与参数。工具的实际动作以对话事件和返回结果为准，不能仅凭界面图标判断。[工具与权限说明](../../../docs/TOOLS_AND_MCP.md)

## 执行记录、长期记忆与改进提案

- **执行记录**：按任务或会话查看轨迹，展开模型与工具调用、真实退出码和评分；点赞/点踩作为独立反馈保存。测试或构建失败时，不能因为模型说“完成”就认定成功。
- **长期记忆**：选择用户、项目或会话作用域，检索记忆，查看历史、软删除与恢复；在待确认变更中接受或拒绝更新。`rule` 只允许用户或采纳流程写入。
- **改进提案**：点击分析会调用模型；运行评测会产生额外模型费用。只有通过门禁的推荐提案才能确认采纳。可按需执行在线监控，下降达到阈值时回滚。没有定时自动进化任务。

自动整理、Langfuse 与 Mem0 默认关闭。评测和 Critic 可能发送隔离用例或已脱敏的轨迹给模型，运行前检查模型、数据范围和费用。详细机制见[学习闭环](../../../docs/LEARNING_LOOP.md)。
