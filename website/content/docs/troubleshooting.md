# 排错与当前限制

## 启动与连接

| 现象 | 先检查 |
| --- | --- |
| 提示找不到后端 Python 环境 | 在 `vera-agent/` 运行 `uv sync --locked --no-dev --extra desktop` |
| 提示桌面窗口依赖缺失 | 确认安装了 `desktop` extra 和 WebView2 Runtime |
| 本地 API 没有就绪 | 在终端运行 `vera-agent\.venv\Scripts\python.exe -m vera_agent.desktop` 查看报错；8000–8100 可能全部被占用 |
| 终端工具找不到 Bash | 安装 Git for Windows，或设置 `VERA_AGENT_BASH_PATH` 指向 `bash.exe` |
| 模型无法回答 | 检查应用的模型配置、服务商地址、密钥和网络；不要把密钥贴入 issue 或截图 |
| 开发前端无法访问 API | 检查 Vite 的 `VITE_API_PROXY_TARGET` 与本地后端端口是否一致 |

## 工作流与数据

| 现象 | 含义与处理 |
| --- | --- |
| 模板看起来正确，但没有结果 | 模板只是定义。确认创建了项目实例、从对话发起运行，并检查节点状态和最终投递。 |
| 刷新后运行停止 | 当前调度在界面中，刷新会中断运行；查看项目 `.agents/runs/` 的状态，当前无恢复端点。 |
| 看板关联了对话，但状态未变化 | 关联不等于验收；检查结果后手动更新工作项状态。 |
| 数据迁移后会话缺失 | 核对应用级和项目级 `.agents/` 都已在应用关闭时备份并恢复。 |

## 已知边界

- 当前只提供 GitHub 源码安装，不提供签名发行包、自动更新或卸载程序。
- 桌面 API 是本地单用户设计；没有公共服务所需的调用者认证。
- 文件范围约束是应用策略，终端命令拥有当前 Windows 用户的系统权限。
- 工作流串行执行、界面调度；节点编辑能力不代表所有节点类型都有独立执行器。
- 模型、MCP 服务与 Skill 的行为取决于用户配置和外部依赖。首页的界面示意不代表真实执行结果。

如果要报告问题，请记录复现步骤、版本、非敏感错误信息与对应节点/接口状态，**不要**附 API Key、完整会话导出或 `.agents/` 中的凭据文件。测试覆盖与未验证场景见[仓库测试说明](../../../docs/TESTING.md)。
