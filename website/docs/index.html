开发文档

从安装和开发开始，了解 VeraAgent 的运行结构、项目边界与扩展方式。文档描述当前实现，不把规划中的能力写成已交付功能。

项目概览

VeraAgent 是面向本地软件项目的 AI Agent 桌面工作台。它将 React 前端、Python 本地 API、模型调用、会话状态与本地工具连接起来。桌面启动后 API 绑定 loopback 地址，当前产品不是托管式多租户服务。

桌面应用Windows + pywebview / WebView2
本地服务Python Starlette API 与 Agent 循环
前端React、TypeScript 与 Vite
模型由用户选择服务商并配置凭据

快速开始

初次运行需要下载依赖并配置模型服务凭据。桌面引导安装和从源码开发是两种独立的使用路径。

Windows 桌面端

需要 Windows 10/11、Node.js 20+、Git for Windows、Python 3.10+、WebView2 Runtime 和网络连接。推送完成后，可从 PowerShell 运行：

npx --yes github:Felix-0625/Agents
这是从 GitHub 获取源码并在本机安装依赖的引导器，不是已发布到 npm Registry 的包，也不是预编译、签名的 Windows 安装程序。首次运行需要联网。

源码开发

仓库用 uv.lock 锁定 Python 依赖，并用 npm lockfile 锁定前端依赖。请使用已提交的锁文件安装。

cd frontend
npm ci
cd ../vera-agent
uv sync --locked --extra desktop --extra dev
cd ..
./start-desktop.ps1

系统结构

React + TypeScript UI
        │ HTTP / WebSocket（loopback）
        ▼
Python Starlette API
        ├─ 会话与项目状态
        ├─ Agent / 模型请求循环
        └─ 文件、命令、Git、MCP 与 Skill 工具

聊天路由接收当前会话、项目与模型配置；Agent 根据模型返回执行工具并将结果回到对话。可观察的是对话、工具调用和工具结果。模型隐藏推理不是执行轨迹，也不应在展示页中模拟成已验证事实。

项目范围与权限边界

绑定项目是记录一个本地路径，并不会复制或隔离整个项目。文件读取/写入范围由应用层策略检查；终端命令仍使用当前 Windows 用户身份运行。

  • 目录权限校验不等于 Windows 系统级沙箱。
  • 用户配置的模型服务可能接收提交给模型的提示词和选定上下文。
  • 文件、命令、Git、MCP 和 Skill 工具可能影响本机或项目，请按具体权限与实现判断。
外部 MCP/Skill 仓库的存在不代表包内容经过安全认证。启用前应检查源码、执行命令、环境变量和网络访问。

MCP 与 Skill

MCP 服务和 Skill 安装/启停属于应用级设置；不能把它们描述成自动按项目隔离的配置。安装扩展前应审查来源及实际执行行为。

市场条目只是发现入口，不是签名、沙箱或安全认证。只启用理解并信任的扩展，避免向不必要的服务提供密钥或本地访问权限。

配置与本地数据

全局模型凭据、应用状态、项目记录和会话数据可能存于不同位置，实际路径取决于启动方式及具体服务路由。修改或迁移前，先按说明备份 `.agents` 数据和凭据配置。

  • 不要提交 `.env`、密钥、MCP 环境值或会话导出。
  • 不要将本地会话/运行轨迹当成通用测试数据。
  • 项目绑定不代表 Agent 只可访问该目录；要结合文件权限与命令能力判断。

已知限制

  • 当前安装流程从源码构建，不提供离线安装、版本固定的发行包或签名安装器。
  • 终端运行不是操作系统沙箱，应用权限 UI 不会降低当前 Windows 用户的系统权限。
  • 工作流模板和界面不自动证明一个完整运行时已执行；需核对实际运行记录、节点状态和返回结果。
  • 可用模型、扩展能力和特定工具行为依赖当前配置与依赖环境。
